## Requirements

- Only a human at a terminal issues, extends or revokes a grant, decided by the same check `qg override` uses (`lib/guard-override.sh`). An agent running `qg grant` is refused by both `templates/claude-hooks/guard_bash.py` and `bin/qg`.
- The grant names its actions and expires; an expired or absent grant behaves exactly as today. Default and maximum duration are decided in row 3 and written in `vault/architecture/qg-cli.md`.
- The grant file lives in the main worktree's git dir beside `.git/qg-tool-path`, where the agent guard already denies writes (`templates/claude-hooks/guard-edit.sh`).
- The grant never allows force push, edits to `~/workspace/vault-quality-gates` `main`, or `qg hooks install --claude --user`.
- Never edit `quality/baseline.tsv`, `quality/checks.tsv`, `quality/config` or `quality/drivers/` to make a gate pass (`templates/claude-hooks/guard-stop.sh`).
- `!` commands in Claude Code inherit `CLAUDECODE`, so `qg` refuses them as an agent; the grant has to cover that path too.
