# S6 binding rules — sandbox, clean environment, branch cleanup

The exact values the S6 work items implement. The plan
`2026-10-20-1022-qg-s6-agent-hooks.md` names which item builds each rule; this file states the rule.

## Sandbox — `bin/qg-sandbox`

| rule | value |
|---|---|
| interpreter | `#!/usr/bin/python3 -I`, stdlib only |
| process | `setsid`; stdin from `/dev/null`; every descriptor above 2 closed; `PR_SET_NO_NEW_PRIVS` |
| grants | each `--write <path>` opened `O_PATH | O_NOFOLLOW`; refused when its real path differs from the given path; a folder gets every filesystem right of the running ABI, a file gets write and truncate |
| scoping | `LANDLOCK_SCOPE_SIGNAL` and `LANDLOCK_SCOPE_ABSTRACT_UNIX_SOCKET` |
| seccomp | architecture other than the native one → kill process; syscall number `>= 0x40000000` → `ENOSYS`; `io_uring_setup` → `ENOSYS`; `socket` with family `AF_UNIX` → `EACCES`; `socketpair` allowed |
| architectures | `x86_64`, `aarch64`; any other exits with one stderr line |
| armed marker | `--armed <file>` is written just before `execvp`; a missing marker means the sandbox never armed |
| minimum ABI | 6; below it the wrapper exits without the marker |

## Sandbox — `qg_sandbox_run` in `lib/qg-sandbox.sh`

`qg_sandbox_run` is the only function that starts a sandbox. It reads `QG_SANDBOX` and
`QG_SANDBOX_WRITES`, which `guard_run_driver` exports from `describe`; it never reads `describe`.

| rule | value |
|---|---|
| private folder | `mktemp -d` mode 700; removed after the run; its path is `QG_PRIVATE` |
| child environment | `env -i` with `HOME=$QG_PRIVATE`, `TMPDIR=$QG_PRIVATE`, `PATH` of the engine, `LANG`, `LC_ALL`, `PUB_CACHE=<real home>/.pub-cache`, `FLUTTER_ROOT` and `FLUTTER_ALREADY_LOCKED=true` when `QG_SANDBOX_SDK` is set, and the `QG_*` names the driver contract passes |
| always writable | `QG_PRIVATE`, `/dev/null`; with `QG_SANDBOX_SDK`, its existing `bin/cache/*.stamp` and `bin/cache/lockfile` |
| tree writes | only the paths in `QG_SANDBOX_WRITES`, each relative to `QG_TREE`, created before the sandbox starts, refused when it resolves outside the tree, names `.git`, or lies under `node_modules` other than `node_modules/.vite` and `node_modules/.cache` |
| report folders | `qg_tool` adds the folder of its report argument to the tree writes |
| runners | a `runner=` runs outside the sandbox under the child environment, as `<runner> <tree> <cache> <sandbox prefix> <argv>`; it may write the tree before it runs the argv, and only the tool is confined. With `QG_SANDBOX=0` it gets `<runner> <tree> <cache> <argv>` |
| `QG_SANDBOX=0` | the command runs without the sandbox, under the same child environment except that `HOME` is the real home |
| failure | missing armed marker → `status: error` naming `qg-sandbox`; a write the sandbox denied is named from the tool's stderr when present |
| record | the row log in `qg-last/<id>/` gets the line `sandbox: armed` |

## Driver `sandbox` and `writes`

A driver absent from this table declares no `writes`. Every built-in driver not listed as `false`
runs sandboxed; a repo driver's whole `run` runs inside `qg_sandbox_run` with `QG_OUT` writable,
unless its `describe` says `"sandbox": false`.

| driver | `sandbox` | `writes` |
|---|---|---|
| `shell`, `checkstyle`, `phpstan`, `phpmd`, `phpcs`, `pint`, `phpinsights`, `composer-dependency-analyser`, `phpunit`, `infection`, `jscpd`, `jscpd-added`, `doc-lint` | false | — |
| `vitest` | true | `coverage quality-reports .nuxt node_modules/.vite node_modules/.cache` |
| `stryker` | true | `.stryker-tmp reports .nuxt node_modules/.vite node_modules/.cache` |
| `nuxt-typecheck` | true | `.nuxt node_modules/.cache` |
| `eslint` | true | — (its report moves to `QG_PRIVATE`) |
| `flutter-test` | true | `.dart_tool build` (coverage goes to `QG_PRIVATE`) |
| `mutation-test` | true | `lib test .dart_tool build reports` |
| `dart-analyze`, `flutter-analyze`, `dart-format`, `dart-code-linter`, `lakos`, `layerlens` | true | `.dart_tool` |

## Clean environment at every entry

Every file in `templates/git-hooks/`, `bin/guard.sh` and `bin/qg` starts `#!/bin/bash -p`. Its first
statement re-executes the script under `/usr/bin/env -i` whenever the environment holds a name
outside the list below. The check reads the environment, never a marker variable. Stdin passes
through.

| kept name | where |
|---|---|
| `HOME`, `USER`, `LOGNAME`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TERM`, `SSH_AUTH_SOCK`, `XDG_RUNTIME_DIR`, `DISPLAY` | every entry |
| `GIT_DIR`, `GIT_INDEX_FILE`, `GIT_WORK_TREE`, `GIT_PREFIX`, `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, `GIT_REFLOG_ACTION`, `GIT_PUSH_OPTION_COUNT`, `GIT_PUSH_OPTION_<n>` | every entry |
| `CLAUDECODE`, `AI_AGENT` | every entry |
| `QG_SKIP_REASON` | git hook templates only |
| `GITHEAD_<sha>`, which git sets for merge hooks | every entry |
| `GUARD_CONFIG_REV`, `GUARD_SHA`, `GUARD_BASE` | `bin/guard.sh` only; every git hook template unsets `GUARD_CONFIG_REV` |
| `QG_CALLER_PATH`, set to the caller's `PATH` | `bin/qg` only; read by `hooks install --user` and the doctor suggestion |
| `VAULT_FRAMEWORK_PATH` | `bin/qg` only; read by `qg init`, which refuses an agent |
| `QG_CLEAN_ENV=1` | set by the restart itself; see `at most one restart` |

`PATH` becomes `/usr/local/bin:/usr/bin:/bin` followed by the entries of the machine tool-path file.
The engine sets `GIT_NO_REPLACE_OBJECTS=1` before it reads any config revision.

## Machine tool-path file

| rule | value |
|---|---|
| path | `<git-common-dir of the main worktree of vault-quality-gates>/qg-tool-path` |
| writer | `qg hooks install --claude --user`, run by the operator, from `QG_CALLER_PATH`: the folder of the first `pnpm`, `node`, `php`, `composer`, `docker` and `hugo` found, in that order, without duplicates |
| entries | absolute, existing folders outside every git work tree; the engine drops any other entry and `qg doctor` fails naming it |
| protection | inside `.git`, so `guard-edit.sh` and `guard_bash.py` deny agent writes; both hooks also deny writes under each listed folder |
| absent | `PATH` is the system folders only; `qg doctor` fails naming `qg hooks install --claude --user` |

## Agent guard additions — `guard_bash.py`, `guard-edit.sh`

| rule | value |
|---|---|
| denied names, assigned, exported or passed through `env` | `BASH_ENV`, `SHELLOPTS`, `BASHOPTS`, `BASH_FUNC_*`, `GIT_REPLACE_REF_BASE`, `GIT_NO_REPLACE_OBJECTS`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_OBJECT_DIRECTORY`, `GIT_EXTERNAL_DIFF`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`, any name that is no plain identifier |
| denied commands | `export -f`; `declare` or `typeset` with both `-f` and `-x` |
| global write denials | `~/.pub-cache`; any folder holding `bin/internal/engine.version` and `packages/flutter_tools`; a direct child of `~/.cache` holding a `copydetect-*` folder; `~/.bashrc`, `~/.bash_profile`, `~/.bash_login`, `~/.profile`, `~/.zshrc`, `~/.zshenv`, `~/.zprofile`; every folder on `PATH` before `/usr/bin`; every folder in the machine tool-path file |
| text match | the denied roots also count inside interpreter code and in `tar -C`, `unzip -d`, `curl -o`, `wget -O` and `git clone` targets |
| narrowed | `RISKY_CODE` and the `ai_agent` and `claudecode` needles apply only when the same command also names git, `.git`, a hook path or the plugin; `RISKY_CODE` is advisory, because a script file the agent writes is never scanned for it |
| allowed | `>&<digit>` and `>&-`; a program whose real path is under `~/.claude/plugins/cache` naming the plugin path |
| python | every hook runs `python3 -I` |

## User-level install

| rule | value |
|---|---|
| targets | `$HOME/.claude/settings.json`, plus `<dir>/settings.json` for each `--config-dir <dir>` given |
| refusal | when `git -C <guard_plugin_dir> rev-parse --path-format=absolute --git-dir` differs from `--git-common-dir`, so a linked worktree's code never becomes the guard |
| doctor | fails when `$HOME/.claude/settings.json` lacks the three entries, and when `~/.claude-factory` exists and its `settings.json` lacks them |

## Branch cleanup runbook

For each branch `qg doctor --all-branches` lists as failing, in its repo. `<src>` is the sha the
doctor prints as the v2 source, the tip of the newest v2 branch.

1. `git switch <branch>`
2. For app.givore.com and dashboard.givore.com only:
   `pnpm install --frozen-lockfile --ignore-scripts && pnpm exec nuxt prepare`
3. `git rm -rq quality ':!quality/baseline.tsv' && git checkout <src> -- quality ':!quality/baseline.tsv'`
4. `qg baseline`, which measures this branch's own values into the v2 `quality/baseline.tsv`
5. `git add quality && qg override --reason "v2 gate config" && git commit -m "chore(quality): gate config v2"`.
   The override matters only where the parent commit has `quality/rules.tsv`; elsewhere the commit is not gated.
6. `qg run push && git push`

A branch nobody needs is deleted instead: `git branch -D <branch>` and `git push origin --delete <branch>`.
When step 6 refuses, the branch keeps its v1 config and the doctor keeps listing it. Delete it or fix
the named rows on it.

## Settled details

### `qg doctor --all-branches`

| question | rule |
|---|---|
| refs read | `refs/heads/*` and `refs/remotes/*/*` except symbolic refs; tags, notes and the stash are never read |
| one line per ref | label precedence `worktree`, then `upstream`, then `stale`; a branch checked out in the main worktree counts as `worktree` |
| live upstream | a configured upstream whose remote-tracking ref exists locally, or, for `branch.<x>.remote=.`, whose local branch exists |
| unrecognised header | listed as `unknown`, with the exit code of its ref kind |
| source | the v2 ref holding `quality/config` with the newest tip committer date; with none, the doctor prints `no v2 source` |
| `--json` | one object `{"source": <sha or null>, "refs": [{"ref", "sha", "state", "version", "config"}]}`; the exit code equals the text form's |
| `qg doctor` on a v1 `HEAD` | exits 1 with a fail line naming `qg doctor --all-branches`, never `qg migrate` |

### Install, remove, status, doctor

| question | rule |
|---|---|
| the three entries | the entries whose command's file name is `guard-bash.sh`, `guard-edit.sh` or `guard-stop.sh`. Install replaces every such entry, whatever its folder, with one entry under the main worktree |
| `hooks remove --claude` | removes the three entries from the repo's `.claude/settings.json` and nothing else; the git hooks stay |
| `hooks remove --claude --user` | removes them from `$HOME/.claude/settings.json` and each `--config-dir` given |
| `hooks status --user` | one line `installed|absent <entry> <file>` per entry and target; exit 0; allowed for an agent |
| doctor targets | always `$HOME/.claude`, and `~/.claude-factory` when that folder exists; another `--config-dir` is not checked |
| hook copy differs from template | doctor fails, naming `qg hooks install` |
| invalid target JSON | install and remove exit 2 and leave the file unchanged |
| tool-path file format | one absolute folder per line, symlinks resolved, trailing `/` dropped, duplicates kept once; an entry for which `git -C <dir> rev-parse --show-toplevel` succeeds counts as inside a work tree |
| `QG_CALLER_PATH` | `bin/qg` sets it from its own caller's `PATH` before the clean restart; a value the caller exports is overwritten |

### Removal of v1

| question | rule |
|---|---|
| where a v1 header exits 2 | `guard_load_checks`, so every command that loads rows: the hooks, `qg run`, `qg list`, `qg explain` |
| key only in `VAULT.md` | `qg config get <key>` prints nothing and exits 1 |
| `qg migrate` | unknown subcommand for everyone: exit 2 with the help text |
| test file | `tests/unit/qg-migrate.bats` becomes `tests/unit/qg-init.bats` with the lib rename |

### `checks/_qg-cases.sh`

A named case whose `ok` line holds `# skip` or `# TODO` is FAILING. A case both absent and skipped is
reported FAILING.

### Sandbox

| question | rule |
|---|---|
| minimum ABI | 6, so signal and abstract-socket scoping always apply; `--max-abi <n>` lowers the ABI the wrapper uses, for tests only, and can never raise it |
| 32-bit entry | the process is killed; tests assert that no socket opened |
| path comparison | a grant is given relative to `QG_TREE`, normalised with `os.path.normpath`, and refused when absolute, when it starts with `..`, when any component is `.git`, when it is `.` or `node_modules`, or when it lies under `node_modules` other than `node_modules/.vite` and `node_modules/.cache`; an empty entry is skipped |
| missing path | checked first; then created as a folder one component at a time, each `lstat` refusing a symlink |
| refused path | the whole run is `status: error` naming the path; the tool never runs |
| `QG_SANDBOX` | exactly `0` runs unsandboxed; any other value or unset runs sandboxed |
| `describe.sandbox` | only JSON `false` opts out; anything else, or unreadable `describe` output, means sandboxed |
| repo driver | always sandboxed; its `describe` `sandbox` is ignored |
| SDK grants | the existing files matching `bin/cache/*.stamp` at top level, and `bin/cache/lockfile` when it exists |
| driver output | reaches `QG_OUT` only through descriptors 1 and 2 |
| paths under the real home | each driver computes them, such as the copydetect venv, before calling `qg_tool` |
| `sandbox: false` drivers and `shell` rows | run through `qg_sandbox_run` with `QG_SANDBOX=0`, so they get the same child environment |

### Clean environment

| question | rule |
|---|---|
| how names are read | from `/proc/self/environ`, never from bash's variable list, which hides `BASH_FUNC_*` and other names that are no plain identifier |
| names that never trigger a restart | `PWD`, `OLDPWD`, `SHLVL`, `_`; `PATH` when it equals the clean `PATH` |
| at most one restart | the restart sets `QG_CLEAN_ENV=1`; a process holding it and any name outside the kept list exits 2, so a forged marker can stop an entry but never skip the restart |
| agent markers | assigning, unsetting, exporting, declaring, `read` or `printf -v` of `CLAUDECODE` or `AI_AGENT` is always denied; a word that merely holds those strings follows the narrowed needle rule |
| `HOME` | kept with the caller's value; `guard-edit.sh` already denies agent writes to `~/.gitconfig` |
| loader variables | `LD_PRELOAD`, `LD_LIBRARY_PATH` and `LD_AUDIT` act on `/bin/bash` before its first line, so `guard_bash.py` denies assigning them; tests use a missing preload path, which only warns |

### Agent guards

| question | rule |
|---|---|
| `python3 -I` in `guard_bash.py` | the script inserts its own folder at `sys.path[0]` before importing `shell_lexer` |
| "the same command" | the whole Bash input, scripts it runs or sources included |
| text match | `~`, `$HOME`, `${HOME}` and absolute spellings, in `-c`, `-e`, heredoc code and script files an interpreter runs |
| write forms | `tar -C` and `--directory=`; `unzip -d`; `curl -o`, `--output` and `--output-dir`; `wget -O`, `--output-document` and `-P`; `dd of=`; `git clone <url> <dir>` |
| `cd` with no argument | moves the checked cwd to `HOME` |
| `PATH` folders before `/usr/bin` | absolute entries only; empty and relative entries are ignored; with no `/usr/bin` in `PATH`, every absolute entry |
| plugin exemption | a path is protected when it lies inside the real path of the main worktree the hooks run from; any other path, a linked worktree included, is editable |
| `export BASH_ENV` with no value | denied |
| `declare -f`, `declare -F`, `declare +x -f` | allowed |
| hook tests | copy the plugin into a writable `$WORK` folder, because `/code` is read-only in the test image |
