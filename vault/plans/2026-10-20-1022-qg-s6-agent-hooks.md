# Close the agent gaps and retire the v1 gate config — plan

## Task

Install the agent guards once at user level. Start every git hook and gate entry from an empty
environment, under `/bin/bash -p`, with a fixed tool path, so no caller variable, exported function
or planted program changes a verdict. Run every driver that executes code from the measured tree in
a Landlock and seccomp sandbox that cannot write outside its declared paths and cannot open a Unix
socket. Add `qg doctor --all-branches`. Delete the v1 `checks.tsv` reader, the `VAULT.md` config
fallback and `qg migrate` once that doctor exits 0 in every gated repo.

The exact rules live in `2026-10-20-1022-qg-s6-agent-hooks.rules.md`; every work item below
implements a section of it.

Keywords: `qg doctor --all-branches`, `bin/qg-sandbox`, `qg_sandbox_run`, `QG_SANDBOX`,
`QG_SANDBOX_WRITES`, `qg_isolated`, `qg_tool`, `landlock`, `seccomp`, `qg-tool-path`,
`guard_bash.py`, `guard-edit.sh`, `BASH_FUNC_`, `env -i`, `hooks install --claude --user`,
`guard_load_checks`, `qg_on_from_v1`, `qg_config_source`.

**Priority when two qualities conflict:** no hidden bypass first, then no ordinary agent command
refused, then less code.

## Decisions

| decision | reason | record |
|----------|--------|--------|
| The sandbox is `bin/qg-sandbox` (Python stdlib) plus `qg_sandbox_run`, per the rules file | no privilege needed; Landlock, seccomp and the armed marker close each verified escape | local |
| `guard_run_driver` exports `QG_SANDBOX` and `QG_SANDBOX_WRITES` from `describe`; `qg_sandbox_run` is the only launcher and owns the child environment; `qg_isolated` keeps only `setsid` and the group kill | one decision, made by the engine from the driver, never from a row a commit wrote | local |
| A tree is writable only through declared paths and report folders, whatever its `.git` is | a linked worktree's `.git` file and `.claude/` are as dangerous as the main one | local |
| Dart drivers run the SDK through a `bin/flutter` shim in `QG_RUN_DIR` that execs the tool snapshot; `QG_FLUTTER` is the shim's path; `qg_dart_env` exports `QG_SANDBOX_SDK` | `<sdk>/bin/flutter` writes the SDK on every call | local |
| Every entry starts `#!/bin/bash -p` and re-executes under `env -i` when its environment holds a name outside the list in the rules file | a marker variable can be forged; a `PATH`-found `bash` can be planted | local |
| The tool folders are one machine file in the main worktree's `.git`, written by the operator's install | a committed key would be absent on most branches; `.git` is already denied to agents | local |
| The guards install at user level for `~/.claude` and each `--config-dir`; commands point at the main worktree | the factory runs Claude with its own config folder | `vault/research/2026-10-18-gate-tools-survey.md` |
| `qg doctor --all-branches` fails on remote-tracking refs, branches with a live upstream and branches checked out in a worktree; other local v1 branches are stale | a stale branch cannot be pushed by mistake, and a human override passes a commit on it | local |
| The cleanup copies `quality/` except `baseline.tsv`, then re-baselines the branch | a copied baseline from a newer branch refuses every push of older code, with no override | local |
| `qg_migrate` is deleted; `lib/qg-migrate.sh` becomes `lib/qg-init.sh` | once every live branch is v2, nothing remains to migrate | local |
| S6 is built in worktree `~/workspace/vault-quality-gates-s6` on `feat/qg-s6-agent-hooks`, then `feat/qg-s6-v1-removal` stacked on it; after any change to the first, the second is rebased and DOD-1 runs on both | the removal merges only after SC-8 | local |

## Scope & non-goals

S6 covers the sandbox, the hook and entry-point changes, the user-level install, the machine
tool-path file, `qg doctor --all-branches`, the v1 and fallback removal, and this repo's v2 config.
The operator installs, merges and commits each repo's config.

Not in scope: sandboxing `shell` rows or Docker runners; limiting reads or TCP; server-side
enforcement; changing a target repo's `quality/bin/` runner; macOS, whose `/bin/bash` is 3.2.

## Sequencing & dependencies

branches and commits this repo's v2 config. SC-8 then exits 0, and the operator merges the second.

## Rollback

`git revert` of either merge on `main` restores the previous engine; reverting the second restores
the v1 reader. `qg hooks install` in each repo after a revert puts the previous hook bodies back.
`qg hooks remove --claude --user` removes the user-level guards. A driver whose sandbox misfires is
rolled back by setting its `describe` to `"sandbox": false` alone.

## Test plan

Bats in `tests/unit/` with temporary repos and a temp `HOME`, run by `./tests/run.sh tests/unit`
in Docker, whose image permits Landlock and seccomp. Sandbox cases use a stub tool that tries each
forbidden write, a Unix socket through both system-call entries, and descriptor 9. SC-3 runs the
real `flutter test`, `vitest` and `stryker` rows on scratch clones.
