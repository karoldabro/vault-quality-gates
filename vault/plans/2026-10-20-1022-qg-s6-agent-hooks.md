# Close the agent gaps and retire the v1 gate config — plan

## Task

Install the agent guards once at user level so they cover every repo a session touches. Start every
git hook and gate entry from an empty environment with a fixed tool path, so no caller variable,
exported function or planted program changes a verdict. Run every driver that executes code from the
measured tree in a Landlock and seccomp sandbox that cannot write the pub cache, the Flutter SDK,
`guard-cache` or `.git`, and cannot reach a Unix socket. Add `qg doctor --all-branches`. Delete the
v1 `checks.tsv` reader, the `VAULT.md` config fallback and `qg migrate` once that doctor exits 0 in
every gated repo.

Keywords: `qg doctor --all-branches`, `bin/qg-sandbox`, `qg_sandbox_run`, `QG_SANDBOX`,
`qg_isolated`, `qg_tool`, `landlock`, `seccomp`, `FLUTTER_ALREADY_LOCKED`, `guard_tool_path`,
`guard_bash.py`, `guard-edit.sh`, `BASH_FUNC_`, `env -i`, `hooks install --claude --user`,
`guard_load_checks`, `qg_on_from_v1`, `qg_config_source`.

**Priority when two qualities conflict:** no hidden bypass first, then no ordinary agent command
refused, then less code.

## Decisions

| decision | reason | record |
|----------|--------|--------|
| `bin/qg-sandbox` is a Python 3 stdlib script run as `python3 -I`. It closes every descriptor above 2. It opens each `--write` path with `O_PATH | O_NOFOLLOW` and refuses one whose real path differs from its given path. Landlock handles every filesystem right of the running ABI and, from ABI 6, scopes signals and abstract Unix sockets | no privilege needed; a committed symlink cannot widen a grant | local |
| The seccomp filter kills the process for any architecture other than the native one, returns `ENOSYS` for x32 numbers (`>= 0x40000000`) and `io_uring_setup`, and `EACCES` for `socket(AF_UNIX)`. It allows `socketpair`, which Node and Dart use for child pipes | a 32-bit entry otherwise reaches the Docker socket | local |
| The sandbox fails closed. It writes the marker file `.qg-sandbox-armed` in the private folder just before `execvp`; `qg_sandbox_run` treats a missing marker as `status: error` naming the sandbox | a tool's own exit code can equal any code the wrapper picks | local |
| `guard_run_driver` reads `describe` `.sandbox`, default `true`, and exports `QG_SANDBOX=1` or `0` to the driver. `qg_sandbox_run` in `lib/qg-sandbox.sh` is the only place that starts a sandbox; `qg_tool` and `qg_isolated` call it when `QG_SANDBOX=1`. Drivers named in Open & deferred declare `"sandbox": false` | one decision, made by the engine from the driver, never from a row a commit wrote | local |
| `qg_sandbox_run` makes a private folder with `mktemp -d` mode 700, sets `HOME` and `TMPDIR` to it, and removes it after the run | tools that call `mktemp` need a writable temp folder | local |
| When `QG_TREE` holds a `.git` folder, the sandbox may write only the paths the driver's `describe` lists in `writes`, created first and refused when they resolve outside the tree. A tree whose `.git` is a file or absent is writable whole | the operator's working tree holds `.git`, `.claude`, `.mcp.json` and hard links into the pnpm store | local |
| Dart drivers run the SDK through a private `bin/flutter` shim, whose path is `QG_FLUTTER`, that execs `dart <sdk>/bin/cache/flutter_tools.snapshot` with `FLUTTER_ALREADY_LOCKED=true`; the shim heads `PATH`; `qg_dart_env` exports `QG_SANDBOX_SDK=<sdk>` | `<sdk>/bin/flutter` writes the SDK on every call | local |
| Every git hook template, `bin/guard.sh` and `bin/qg` re-execute once under `/usr/bin/env -i` keeping `HOME`, `USER`, `LOGNAME`, `LANG`, `LC_*`, `TERM`, `SSH_AUTH_SOCK`, `XDG_RUNTIME_DIR`, `GIT_*`, `GUARD_CONFIG_REV`, `CLAUDECODE` and `AI_AGENT`, with `PATH=/usr/local/bin:/usr/bin:/bin`. The engine appends `guard_tool_path` from the config revision. Stdin passes through | `bash -p` alone still hands `BASH_FUNC_*` to every child; a fixed list closes `NODE_OPTIONS`, `LD_PRELOAD` and the next variable nobody listed | local |
| The guards install at user level, with commands under the main worktree of this repo. Install compares `git -C <guard_plugin_dir> rev-parse --path-format=absolute --git-dir --git-common-dir` | one install covers every repo; a linked worktree's code never becomes the guard | `vault/research/2026-10-18-gate-tools-survey.md` |
| `RISKY_CODE` and the `ai_agent`/`claudecode` needles apply only when the same command also names git, `.git`, a hook path or the plugin | at user level a plain one-liner in any repo hits them | local |
| Write denials for `~/.pub-cache`, a Flutter SDK, a venv folder and shell startup files are global. An SDK is any folder holding `bin/internal/engine.version` and `packages/flutter_tools`. A venv folder is a direct child of `~/.cache` holding a `copydetect-*` folder | a user-level hook knows no repo's config | local |
| `qg doctor --all-branches` fails on remote-tracking refs, branches with a live upstream and branches checked out in a worktree; it lists other local v1 branches as stale | a stale branch can no longer be pushed by mistake, and a human override passes a commit on it | local |
| `qg_migrate` is deleted; `lib/qg-migrate.sh` becomes `lib/qg-init.sh` holding `qg_init` | once every live branch is v2, nothing remains to migrate | local |
| S6 is built in worktree `~/workspace/vault-quality-gates-s6` on two branches: `feat/qg-s6-agent-hooks`, then `feat/qg-s6-v1-removal` stacked on it. After any change to the first, the second is rebased and DOD-1 runs on both | the removal merges only after SC-8 | local |

## Sequencing & dependencies

W-1..W-3 first, so the operator can start the branch cleanup at once. Then W-10..W-15 (sandbox),
W-16..W-23 (hooks and entry points), W-24, W-25 and W-29 on `feat/qg-s6-agent-hooks`. W-26..W-28 and

merges the first branch, reinstalls the git hooks, installs the user-level guards, cleans the
branches and commits this repo's v2 config. SC-8 then exits 0, and the operator merges the second
branch.

## Rollback

`git revert` of either merge on `main` restores the previous engine; reverting the second restores
the v1 reader for any branch still on v1. `qg hooks install` after a revert puts the previous hook
bodies back. `qg hooks remove --claude --user` removes the user-level guards, and
`qg hooks install --claude` in a repo restores a per-repo copy. A driver whose sandbox misfires is
rolled back by changing its `describe` to `"sandbox": false` alone.

## Test plan

Bats in `tests/unit/` with temporary repos and a temp `HOME`, run by `./tests/run.sh tests/unit`
in Docker, whose image permits Landlock and seccomp. Sandbox cases use a stub tool that tries each
forbidden write, a Unix socket through both system-call entries, and descriptor 9. SC-3 runs the
real `flutter test`, `vitest` and `stryker` rows on scratch clones.
