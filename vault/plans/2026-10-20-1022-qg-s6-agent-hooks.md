# Close the agent gaps and retire the v1 gate config — plan

## Task

Install the agent guards once at user level so they cover every repo a session touches. Close the
caller-environment bypass (`BASH_ENV`, `ENV`, exported functions, a planted `PATH`). Run every
host-run test suite in a Landlock and seccomp sandbox that cannot write the pub cache, the Flutter
SDK, `guard-cache` or `.git`, and cannot reach the Docker socket. Add `qg doctor --all-branches`.
Delete the v1 `checks.tsv` reader, the `VAULT.md` config fallback and `qg migrate` once that doctor
exits 0 in every gated repo.

Keywords: `qg doctor --all-branches`, `bin/qg-sandbox`, `qg_isolated`, `qg_tool`, `landlock`,
`seccomp`, `FLUTTER_ALREADY_LOCKED`, `guard_bash.py`, `guard-edit.sh`, `BASH_ENV`, `BASH_FUNC_`,
`bash -p`, `hooks install --claude --user`, `guard_load_checks`, `qg_on_from_v1`, `qg_config_source`.

**Priority when two qualities conflict:** no hidden bypass first, then no ordinary agent command
refused, then less code.

## Decisions

| decision | reason | record |
|----------|--------|--------|
| `bin/qg-sandbox` is a Python 3 stdlib script: Landlock handles every filesystem write right of the running ABI; seccomp returns `EACCES` for `socket(AF_UNIX)` and `ENOSYS` for `io_uring_setup`; both are set after `PR_SET_NO_NEW_PRIVS`, then it `execvp`s | no privilege needed; `landrun` is not installed and is a Go binary | local |
| The sandbox fails closed: ABI below 3, an unknown architecture or a failed syscall exits 125, and the driver writes `status: error` | an unsandboxed suite looks measured | local |
| Drivers declare `"sandbox": true` in `describe`; `flutter-test`, `mutation-test`, `vitest` and `stryker` do; `phpunit` and `infection` do not, because their runner needs Docker | the engine decides from the driver, never from a row a commit wrote | local |
| A tree holding a `.git` folder is writable per top-level entry except `.git` and `node_modules`; `node_modules/.vite` and `node_modules/.cache` are created first and writable | Landlock grants paths and cannot exclude a subfolder | local |
| Dart suites run the SDK as `dart <sdk>/bin/cache/flutter_tools.snapshot` with `FLUTTER_ALREADY_LOCKED=true`; a private `bin/flutter` shim on `PATH` does the same for `mutation_test.xml` | `<sdk>/bin/flutter` writes the SDK on every call | local |
| Git hook templates and `bin/guard.sh`, `bin/qg` start `#!/bin/bash -p`, prepend `/usr/local/bin:/usr/bin:/bin` to `PATH`, and pass on an environment without `BASH_ENV`, `ENV` or `BASH_FUNC_*` | `bash -p` reads no `BASH_ENV` and imports no function | local |
| The guards install at user level, with commands under the main worktree of this repo | one install covers every repo, ungated ones included | `vault/research/2026-10-18-gate-tools-survey.md` |
| Write denials for `~/.pub-cache`, a Flutter SDK and a venv folder are global: an SDK is any folder holding `bin/internal/engine.version` and `packages/flutter_tools`; a venv folder is a direct child of `~/.cache` holding a `copydetect-*` folder | a user-level hook knows no repo's config | local |
| `qg migrate` is deleted with the v1 reader; a v1 file exits 2 naming `qg doctor --all-branches` | once every branch is v2, nothing remains to migrate | local |
| S6 is built in worktree `~/workspace/vault-quality-gates-s6`, branch `feat/qg-s6-agent-hooks`; the v1 removal is a second branch, `feat/qg-s6-v1-removal`, stacked on it | the removal merges only after SC-8 | local |

## Rollback

`git revert` of either merge on `main` restores the previous engine; the second revert restores
the v1 reader for any branch still on v1. `qg hooks remove --claude --user` removes the user-level
guards, and `qg hooks install --claude` in a repo restores a per-repo copy. A driver whose sandbox
misfires is rolled back by reverting its `describe` line alone.
