# qg S5 docs repos — test design

The contract document is `2026-10-19-1930-qg-s5-docs-repos.md`. It carries the success criteria and
the work items each row cites. Every backlog row is advisory until the testing loop confirms it
against the written code. `QG_FILES` at commit holds added, copied, modified and renamed paths only
(`lib/guard-diff.sh:21`), so a deleted path never reaches the driver.

## Test design dossier

### DT-1 Counting a doc-lint finding (W-3 steps 6 and 7)

| rule | finding | condition | counted | row |
|---|---|---|---|---|
| R1 | `L<n>` | on an added line | 1 | T-1 |
| R2 | `L<n>` | on an unchanged line of a changed file | 0 | T-2 |
| R3 | `L<n>` | in a plain rename (similarity 100%) | 0 | T-30 |
| R4 | `FILE` | file is new | 1 | T-3 |
| R5 | `FILE` | the parent's version has the code | 0 | T-4 |
| R6 | `FILE` | the parent's version lacks the code | 1 | T-5 |
| R7 | `FILE` | merge; only the second parent has the code | 0 | T-6 |
| R8 | `FILE` | plain rename; the old path has the code | 0 | T-19 |
| R9 | `x<n>` (DUP1) | any | as `FILE` | T-7 |
| R10 | `FILE` | both versions get the code from a config-revision subfolder `VAULT.md` | 0 | T-31 |
| R11 | any | file has no `type:` and sits in a top-level document folder | linted | T-8 |

| rule | condition | outcome | row |

| E2 | `guard_doc_lint` unset, empty, not starting with `/`, `~/…`, a folder, missing, dangling or not executable | `status: error` naming the key | T-21, T-36 |

### Partitions

- Changed paths: a space, a leading `-` (passed as `./-x.md`), depth 5, a root file; `.txt`, `.MD`,
  `.markdown` and `VAULT.md.bak` are not linted and are not skip files.
- Changed-file count: 0, 1, 300 (more than one `xargs` batch).
- Added findings: 0, 1, 10, 11. The engine prints `+N more` and caps findings; the driver only counts.
- Rename similarity: 29%, 31% and 100%, against the engine's `-M30%`.

### Invariants

- P-1 `metric` equals the number of counted findings and is never negative.
- P-2 The same staged tree, parents and config revision give a byte-identical `result.json`.
- P-3 An unstaged edit to any `.md`, `.doc-lint`, `VAULT.md` or `quality/config` never changes `metric`.
- P-4 Adding one finding line raises `metric` by exactly 1.
- P-5 Reordering `QG_FILES` leaves `result.json` unchanged.
- P-6 A run at a config revision without an earlier run's `.doc-lint` sees only its own revision's files.
