# Gate the two non-code repos, `~/vault/givore` and givore.com — plan

## Task

Give `~/vault/givore` a commit gate that lints the documents a commit changes, and givore.com a push
gate that builds the Hugo site, both set up by the operator with `qg init --profile`. Add a built-in
`doc-lint` driver that counts only the findings a commit adds and that no `.doc-lint` file, frontmatter
`type:` change or environment variable can silence. Make `qg init` protect the gate files by exact
path. Rewrite the two Givore indications on the gate to name `qg`.

Keywords: `doc-lint`, `drivers/doc-lint.sh`, `guard_doc_lint`, `qg_kit_config_key`,
`qg init --profile docs`, `templates/init/docs.tsv`, `templates/init/hugo.tsv`,
`guard_protected_paths`, `qg_added_only`, `.doc-lint`, `DOC_LINT`, `BASH_ENV`.

**Priority when two qualities conflict:** no hidden bypass first, then a gate that refuses only what
the commit added, then less code.

## Decisions

| decision | reason | record |
|----------|--------|--------|
| The docs profile's `doc-lint` row uses a built-in `doc-lint` driver, not a shell row | a shell row inherits the caller's environment and lints whole files | local |
| The driver lints the staged tree after replacing every `.doc-lint` and `VAULT.md` in it with the config revision's copies, and writes empty root ones when that revision has none | both walks then stop inside the measured tree, and only committed configuration applies; copying the 174 MB tree per commit costs more | local |
| The driver passes each file as `./<path>` | doc-lint treats a bare `plans/x.md` with no `type:` as outside the document folders | local |
| A line finding counts only on an added line; a file-level finding counts only when no parent's version of that file, linted the same way, has that code | old findings in shared files would refuse most commits | local |
| Every added or changed `.doc-lint` or `VAULT.md`, and every change to a file's type as doc-lint reads it, counts one finding | each one silences checks; a human passes a legitimate one with `qg override` | local |
| The linter path is `guard_doc_lint` in `quality/config`, read with `qg_kit_config_key`; `qg init --profile docs` writes it from `VAULT_FRAMEWORK_PATH`, else `$HOME/workspace/vault/bin/doc-lint.sh` | a commit cannot repoint the linter that judges it | local |
| `qg_dart_config_key` moves to `lib/qg-driver-kit.sh` as `qg_kit_config_key`; `lib/qg-dart.sh` calls it | one reader of gate keys per driver side | local |
| `qg init` protects `quality/checks.tsv quality/baseline.tsv quality/rules.tsv quality/config quality/drivers`, plus every tracked `.doc-lint` and `.doc-lint` for docs | a `quality/` prefix protects unrelated files | local |
| `templates/init/hugo.tsv` stays as written | its row builds in 4.4 s with the CI hugo version | local |
| S5 is built in worktree `~/workspace/vault-quality-gates-s5`, branch `feat/qg-docs-repos` from `main` `3f43b43` | the live gate runs from `main`'s working tree | local |

## Rollback

Before the operator's init commits, `git revert` of the merge on `main` removes the driver. After
them, a repo returns to ungated with `qg hooks remove` and a commit deleting `quality/checks.tsv`
under `qg override`. The indication commit in `~/vault/givore` reverts on its own.

## Test plan

Bats in `tests/unit/` with temporary repos, run by `./tests/run.sh tests/unit` in Docker. The driver
tests use the fixture linter of W-2; one case runs the real framework doc-lint when it is present
and skips otherwise. SC-3 and SC-4 run on scratch clones of the live repos.
