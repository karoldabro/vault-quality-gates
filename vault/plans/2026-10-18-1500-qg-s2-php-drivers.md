# PHP drivers and the recycling-api v2 migration — plan

## Task

Give the gate nine built-in PHP drivers, move the driver runtime into its own library, route driver
findings through one printer, fix recycling-api's runners, and prepare recycling-api's 32 gate rows in
the v2 format with a row-parity proof. All code lands in worktree `~/workspace/vault-quality-gates-s2`,
branch `feat/qg-php-drivers`. Recycling-api files are prepared under `migrations/recycling-api/`; the
operator copies them and commits.

Keywords: `lib/qg-driver.sh`, `lib/qg-row.sh`, `lib/qg-driver-kit.sh`, `guard_run_driver`,
`guard-report-errors.sh`, `qg explain`, `guard_refusal`, `QG_RUN_DIR`, `drivers/<name>.sh`,
`in-tree.sh`, `in-server.sh`, `lock-check.sh`, `qg-parity-recycling-api.sh`, `migrations/recycling-api`.

**Priority when two qualities conflict:** no new bypass first, then a row's verdict unchanged by the
migration, then less code.

| decision | reason | record |

| `lib/qg-row.sh` holds `guard_err`, `guard_row_field`, `guard_substitute`, `guard_args_kv`, `guard_args_argv`; `lib/qg-driver.sh` holds the engine side of drivers; both and `lib/guard-metrics.sh` source `qg-row.sh` | one parser for the row and args grammar, and no file depends on one that depends on it | local |
| `lib/qg-driver-kit.sh` holds the driver side shared by built-ins; `drivers/phpstan.sh` uses it; a repo driver stays self-contained, as the contract's `todo.sh` example | nine copies of the same helpers otherwise | local |
| Built-in drivers share the keys `runner bin files=changed paths=<dir,dir> include=<ERE> exclude=<ERE> lines=added`; `files=changed` replaces phpstan's `paths=changed` | one meaning per key; no repo uses `paths=changed` yet | local |
| With `files=changed` and no matching file, a driver writes `measured 0` and runs nothing | v1 rows write an empty report in that case | local |
| `lines=added` counts findings on added lines only; a line-less finding is printed, never counted | the v1 `guard-added-lines.sh --checkstyle` rule | local |
| `qg_added_only` maps each finding path to a `QG_TREE`-relative path (strip `QG_TREE/`, `/app/`, `./`); a path not in `QG_TREE` is `status: error` | an unmatched path would silently count 0 | local |
| Each driver states which tool exit codes mean measured; any other is `status: error` (table in `vault/architecture/qg-builtin-drivers.md`) | phpmd exits 2 on violations, 1 on a crash | local |
| The kit deletes a driver's report path inside `QG_TREE` before running the tool; a missing report afterwards is `status: error` | a crash must never re-read the last run's report | local |
| All nine drivers declare `needs_tree: true` | a commit row never measures, or writes into, the working tree | local |
| `metric` equals the v1 parser except pint, whose `metric` counts failing files, and phpstan on a v1 `phpstan` row; `format` and `format-staged` take new ids `format-files` and `format-staged-files` | a count says how much to fix; both rows are `kind: diff` with threshold 0, so the verdict is unchanged | local |
| `gate-config-touched` takes the new id `protected-paths-touched` | the protected list grows, so the row reads 1 where v1 read 0 | local |
| The engine exports `QG_RUN_DIR`, created per invocation and deleted at exit; `qg_shared_report` caches one tool report there, keyed by `QG_TARGET`, `QG_TREE` and the args without `metric=`, written to a temporary file then moved | the four insights rows and two cda rows share one run, and no report crosses a run or a target | local |
| `bin/guard-report-errors.sh` takes `--limit <n>`; a HEAD without `quality/rules.tsv` reads as an empty map; an explicit unreadable `--map` still exits 2 | the push refusal and `qg explain` use it in every repo | local |
| `qg explain` prints findings through the printer for driver rows only; a shell row keeps its `output.txt` | the printer would re-run a shell row against the current index | local |
| `guard.sh baseline --only <ids>` measures those rows, records every other row as skipped so it keeps its line, and exits 2 writing nothing when a named row yields no number | the operator baselines new ids without clearing accepted reasons or dropping a row | local |

| `mutation` and `tests-suite` call the tools directly (`env XDEBUG_MODE=coverage vendor/bin/...`), not `composer <script>`; the phpunit driver's `reset=<path>` empties a file before the run | a composer script is unprotected and would let a commit rewrite the command | local |
| `guard_protected_paths` in `migrations/recycling-api/config` adds `quality/drivers quality/config`, every file a driver row names in `config=`, `ruleset=`, `standard=` or `runner=`, every driver default config (`infection.json5`), and `docker-compose.override.yml compose.yaml compose.yml`; `quality/bin` already covers the runners and `lock-check.sh`. | Prepared recycling-api files live in `migrations/recycling-api/`; `apply.sh <checkout>` copies them and commits nothing; under `CLAUDECODE` or `AI_AGENT` it exits 2 unless the checkout's real path is under the real path of `/tmp` | the agent guards forbid an agent `quality/config` in any repo; `TMPDIR` is caller-controlled | local |
| Rows with no driver in this session stay `shell` in v2 form; a shell row whose script reads a key this session changes is treated as changed | the v2 loader parses `parser= artifact= -- cmd` into the v1 command (`lib/guard-metrics.sh:164-168`) | local |
| Parity runs in two `git clone --shared` scratch clones with no hooks, `vendor/` copied (`cp -a`) and `.env` copied from the live checkout; the old clone carries `7add7c29`'s rows so both sides run `docker compose run` on their clone | the live checkout is in use, and its running container mounts only it | local |

## Rollback

Every change to this repo reverts with `git revert` on `main` while no repo has committed the v2
recycling-api config. After the migration commit, the order matters: the S1 engine loads v2 but
refuses the drivers `pint`, `phpmd` and the rest as unknown. So the operator first reverts the
recycling-api migration commit with `qg override` while S2 is still on `main`, then reverts S2.

## Test plan

Bats unit tests in `tests/unit/`, run by `./tests/run.sh tests/unit` (image `tests/Dockerfile`). Each
driver test feeds recorded tool reports and real exit codes through a fake `vendor/bin/<tool>` and a
fake runner that records its argv, then compares `metric` with the v1 parser on the same report. End
to end: `checks/qg-parity-recycling-api.sh` on scratch clones of recycling-api with the real container
tools.

## Test design dossier

**Lock check** (`lock-check.sh`), outcome per case:

| vendor/ = tree lock | package differing from `HEAD:composer.lock` | runner | tree is the checkout | outcome |
|---|---|---|---|---|
| no | any | either | — | exit 2: vendor/ vs composer.lock |
| yes | none, or a `packages` entry outside every dev closure | in-tree | no | runs |
| yes | `packages-dev` entry, a dependency of one, or a `packages` entry inside a dev closure | in-tree | no | exit 2: tool changed |
| yes | any | in-server | — | runs; the commit gate already judged the lock |
| yes | none | in-tree | yes | exit 2: working checkout |

**`baseline --only a,b`:** a named row with a number is rewritten; a named row with none exits 2 and
leaves the file byte-identical; an unnamed row keeps its line byte for byte; no line is invented.

**Parity verdicts:** clean = seeded is VACUOUS (exit 2); both sides unmeasurable is VACUOUS; a timeout
exits 2; a kept id with equal seeded values is SAME; a kept id with different values is DIFF (exit 1);
a new id is listed for the operator.

**Fault hypotheses:** a stale report read after a crash; a shared report reused across targets; a
finding path that never matches an added line; an exit code read on the wrong side; an empty file set
that scans the whole tree; a refusal swallowed when the printer fails; a compose file swapped by the
caller.

**Invariants:** a driver's `metric` equals the v1 parser on the same report, byte for byte. Every
error partition writes no number. Two runs on the same input write the same `result.json`. A finding's
path form (`QG_TREE/`, `/app/`, `./`, bare) never changes the `lines=added` count. Under `lines=added`
a finding on an added line adds exactly 1, and one on an unchanged line adds 0.
