## Decisions & trade-offs

| decision | alternative rejected | why it lost |
|---|---|---|
| Copy `.nuxt` from the checkout that owns `node_modules`, never `nuxt prepare` in the tree | `nuxt prepare` in the tree | it runs the staged `nuxt.config.ts` as host code and lets it generate the rules that judge it |
| Lock check on the used lock's tool closure (devDependencies, `nuxt`, `@nuxt/cli`) against `HEAD` | compare the staged `pnpm-lock.yaml` with the installed one | tools run from the installed `node_modules`; the staged lock decides nothing about them |
| Lock check inline in `in-node.sh` | a sourced `pnpm-lock-check.sh` | the engine copies a runner alone; a sibling would be missing or the commit's own |
| A `jscpd` whole-repo driver sharing `qg_jscpd_report` with `jscpd-added` | keep dashboard's `duplication` as a `shell` row | the shell row runs `pnpm dlx` from the repo folder, which reads the commit's `.npmrc` |
| `pnpm` under `env -i` | unset `npm_config_*` and `pnpm_config_*` | pnpm 11 reads `PNPM_CONFIG_*` in any letter case |
| Parity clones run their own offline `pnpm install` | `cp -al` of the live `node_modules` | a shim or a tool writing in place would change the live checkout |
| `tests-suite-failed` counts failed tests | keep `tests-suite` on the exit code | a count says how much is left; the row is `kind: diff` with threshold 0, so the verdict is unchanged |
| `nuxt` init profile keeps `shell` rows | runner-free driver rows | a staged tree has no `node_modules`, so every row would be unmeasurable |
