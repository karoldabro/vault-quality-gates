# qg-guard-scope — plan

## Task
Make the user-level agent guards (`templates/claude-hooks/guard-bash.sh`, `guard-edit.sh`, `guard-stop.sh`) enforce gate rules only where a gate git hook is installed. The integrity rules, which protect the guard's own install and the gate's tools, keep binding everywhere. The uncommitted run-time-value relaxation in `~/workspace/vault-quality-gates-opencmd` lands with it.
Keywords: `guard_bash.py`, `guard-edit.sh`, `guard-stop.sh`, `gated.py`, `vault-guard-start`, `Integrity`, `gate()`.

## Open & deferred
- needs the operator: run `~/workspace/vault-quality-gates/checks/qg-scope-SC-6.sh` after the fast-forward below. Until then the live guard refuses it.
- needs the operator: fast-forward `main` with `git -C ~/workspace/vault-quality-gates merge --ff-only fix/guard-open-commands`. Every session runs the hooks from that main worktree, and the guard refuses an agent changing it.
- accepted: some commands from an ungated cwd reach a gated repo unchecked by the agent guard. They reach it through a computed path, a relative path inside opaque text, or a non-shell script. Trusted and installed scripts go unchecked too. That repo's own pre-commit hook still runs on the commit.
- accepted: a computed `cd` followed by a writing git command stays denied everywhere. The guard cannot tell whether that folder is the plugin main worktree.
- accepted: inside gated repos the guard allows a computed program name, a computed write target and `python3 -c` with a `$var`. It still denies them when the same command names git, a hook, qg or the plugin. The operator chose this on 2026-10-21.
- accepted: writing a `systemd --user` unit or a crontab can later run git without the agent markers. The operator wants `systemctl --user restart` allowed, so these stay unguarded.
- deferred: files pulled in by an `include.path` of the global git config, and `$XDG_CONFIG_HOME/git/config` when XDG is not `~/.config`, are not protected.

## Decisions

| decision | reason | record |
|----------|--------|--------|
| A repo is gated when `<common dir>/hooks/pre-commit` or `pre-push` holds `# vault-guard-start`. It is also gated when its `.git` file, gitdir or hooks folder cannot be read, or `<common dir>/config` sets `hookspath` | the guard protects the git hook; with no hook there is nothing to bypass, and anything unclear fails closed | local |
| `templates/claude-hooks/gated.py` holds `repo_root()` and `is_gated()` for all three hooks; it walks the filesystem and runs no `git` | one rule, one home, low per-call cost | local |
| Gate rules call `gate(msg, *paths)`. It appends `(msg, paths, ctx.cwd)` to `PENDING` and returns, so scanning continues. `main()` raises `Deny(PENDING[0])` after the whole scan when the command is in scope | a raise mid-scan would skip later integrity checks, and scope is only known once every nested text has been read | local |
| `SCOPE_PATHS` collects paths during the scan: every lexer word with a `/`, `~` or `.`/`..`, split on `=` and `:`, resolved against `ctx.cwd` at that point. It also collects every `TEXT_PATH` match in every raw text `scan_script` reads, quoted words, heredocs and here-strings included | quoted or piped shell text holds its paths as plain text | local |
| The command is in scope when a `SCOPE_PATHS` entry, a recorded `ctx.cwd` or a recorded `gate()` path lies in a gated repo. Every `gate()` reached from `check_git` passes the effective `cwd`, the `where` list and the `ctx.gitenv` values | `cd .. && git -C repo commit -n` and `GIT_DIR=` forms must resolve to the gated repo | local |
| Integrity rules raise `Integrity(Deny)` unconditionally; their list is in W-3 | an agent anywhere can disable the guard or poison the gate's tools through these | local |
| A denial message ends with the gate suffix for `Deny` and an integrity suffix for `Integrity` | in an ungated repo there is no commit gate to fix | local |
| `guard-stop.sh` runs `gated.py`; exit 3 means ungated, every other exit means gated | a Python crash exits 1 and must not read as ungated | local |
