# 2026-11-03-1022-qg-human-proof — plan

## Task

Make `qg override`, `qg grant` and `QG_SKIP_REASON` pass for a human in a WSL terminal by ending the
parent walk in `lib/guard-override.sh` at WSL's root-owned `Relay(<n>)` process. Make
`templates/claude-hooks/guard_bash.py` deny `qg override` and `qg grant` reached through a wrapper
that detaches or fakes a terminal. State in the contract that the human check is a speed bump and
that CI running `qg verify <range>` is the enforcing gate.

Keywords: `guard_override_ancestors_clean`, `_guard_override_walk`, `Relay(`, `osrelease`,
`scan()`, `CMD_WRAPPERS`, `check_qg`.

## Open & deferred

- open: unverified on a real WSL2 host; this machine is native Linux. C5 needs the operator's WSL2 terminal.
- open: unverified on WSL1. Whether WSL1 names the parent `Relay(<n>)` is unknown; if it does not, WSL1 stays refused.
- accepted: a same-user agent can still pass the human check. It can run `setsid -f env -i script -qec "<cmd>" /dev/null` through an interpreter `guard_bash.py` does not parse (`python3 -c`, `perl -e`), open a new WSL session through a Windows-side launcher, or edit `.git/hooks/pre-commit`. No local check can stop that. The contract says so, and CI `qg verify <range>` is the gate that binds.

- `guard_bash.py` `scan()` unwraps `setsid` and `env` as wrappers but treats `script` as an ordinary command, so `qg override` inside `script -qec "..."` reaches no `check_qg` · read `scan()` lines 205-240 · 2026-11-03.
- Every gate entry re-execs under `env -i` with a kept-list (`lib/qg-clean-env.sh`) and the hook shebangs are `#!/bin/bash -p`, so `BASH_ENV` and exported functions do not reach the walk · read `lib/qg-clean-env.sh`, `templates/git-hooks/pre-commit` · 2026-11-03.
- `/proc/<pid>/comm` and `/proc/<pid>/status` of a root process are readable by any user; `/proc/<pid>/environ` is not · Linux procfs permissions · 2026-11-03.
- Each repo's `.git/hooks/` and `.git/config` are writable by the user, so a local hook cannot be locked against a same-user agent · `ls -ld .git/hooks` · 2026-11-03.

## Decisions

| decision | reason | record |
|----------|--------|--------|
| The walk ends clean at a process whose `/proc/<pid>/comm` matches `Relay(<digits>)`, whose `Status` `Uid:` real uid is 0, on a kernel whose `/proc/sys/kernel/osrelease` contains `microsoft` in any case | WSL's init owns that process; a user-level agent cannot create a root process | local |
| The Relay test runs at the top of each walk step, before the environ read, for every pid except `$$` | the environ read is what fails on WSL | local |
| The walk body moves to `_guard_override_walk <proc root> <pid>`; `guard_override_ancestors_clean` calls it with `/proc` and `$$` | tests drive it with a fake proc tree; production takes no input an agent sets | local |
| `guard_bash.py` reads, after a wrapper, each argument holding a space and each trailing run that starts with `qg`, `guard.sh`, `git` or a shell | catches `script -c "qg override"`, `systemd-run --user qg override` and `env -u CLAUDECODE qg override`; reading every suffix took 37 s on a 300-word command | local |
| No sudo password and no root-owned engine | the hook files stay user-writable, so neither stops a same-user agent | local |

## Scope & non-goals

Covers the WSL refusal and the wrapper denials in the Claude Code guard.

Not covered: interpreters (`python3 -c`, `perl -e`, `node -e`) in `guard_bash.py`; a password or
root-owned proof; WSL1 if it lacks `Relay(<n>)`; macOS.
