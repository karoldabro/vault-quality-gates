# qg S3 web drivers — test design

The contract document is `2026-10-18-1930-qg-s3-web-drivers.md`. It carries the success criteria
and work items each backlog row cites.

## Test design dossier

**`in-node.sh`**, outcome per case:

| event | case | outcome |
|---|---|---|
| commit | main `.nuxt` lacks `eslint.config.mjs` or `tsconfig.app.json`, or main has no `node_modules` | exit 2; tree unchanged |
| commit | a tree `.nuxt` exists | replaced by main's copy; removed at exit |
| commit | a staged `nuxt.config.ts` or tree `.nuxt` loosens `strict` and writes a marker | values unchanged; no marker |
| either | tool closure of the used lock differs from `HEAD` (a devDependency, a transitive package, `nuxt`, `@nuxt/cli`) | exit 2 naming the first 10 and the fix |
| either | only a package outside the closure differs | runs |
| either | a lock missing or not v9 | exit 2 |
| either | `NODE_OPTIONS=--require <marker>` inherited | runs; no marker |
| push | in the main checkout | links, copies and deletes nothing |
| push | `node_modules` or `.nuxt` missing in `<tree>` | exit 2 |

**`tools-changed`:** 0 for identical locks and for changes outside the closure; one per package name
bumped, added or removed in either closure, scoped names included; a peer-suffix-only change counts 0;
the count is the same with the two locks swapped; a missing or non-v9 staged lock is unmeasurable.

**`apply.sh`:** each refusal exits 2 and copies nothing. It refuses a checkout with no v1 header. It
refuses an agent environment, even an empty one, with a checkout outside the real `/tmp`, through a
symlink or a `TMPDIR` under `$HOME`. It refuses a hook with no `GUARD=`, hooks naming different
engines, or an engine lacking a named driver. It refuses a `parity.tsv` that is absent or holds a DIFF,
VACUOUS or unmeasured row. `--branch-steps` copies nothing in any environment. It exits 2 with empty
output on an absent `branches.tsv`, a missing branch or an unmeasured row. It lists for
`qg baseline --only` exactly the repo rows worse than the release baseline by the row's `direction`.

**Parity verdicts:** a kept id is SAME when old and new agree at seed1 and seed2, DIFF otherwise. A
renamed row is NEW when its new seeds are numbers and differ from new-clean. A count row whose seed2
equals seed1, a seed equal to its clean value, or an unmeasured side is VACUOUS. The script exits with
the worst row. A branch merge conflicting inside `quality/`, `VAULT.md` or a protected path, or an
unmeasured row after a merge, exits 2.

**`qg_pnpm_isolated`:** each hostile source alone and all together leave `registry` public,
`@jscpd:registry` empty and `pnpm store path` under the gate cache. `HTTPS_PROXY`, `https_proxy` and
`NODE_EXTRA_CA_CERTS` never reach pnpm. A second `dlx` runs without network.

**Invariants:** a driver's `metric` equals the v1 computation on the same output, compared as numbers.
The one difference: app's typecheck rows read a non-zero exit with no `error TS` as `status: error`,
where app v1 printed 0. Every error case writes `metric: null`. Two runs write the same bytes, and
permuted findings change nothing. The `lines=added` count does not change with path form. `errors`
never exceeds `problems`. Rows differing only in keys left out of the cache key make one tool call. A
sibling config the row does not name changes nothing. Runner argv never names a path outside `QG_TREE`.

**Fault hypotheses:** a stale report or junit read after a crash; a cache key dropping a key by prefix
(`rules-x=`) or a `metric=` after `--`; the live `.nuxt` deleted on push; `store-dir` read from one
config file only; a lock pointing the same version at another tarball, since only name and version are
compared (owner S6).
