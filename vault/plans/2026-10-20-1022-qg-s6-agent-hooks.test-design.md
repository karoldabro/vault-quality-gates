# qg S6 agent hooks — test design

The contract document is `2026-10-20-1022-qg-s6-agent-hooks.md`; the values every row asserts are
in `2026-10-20-1022-qg-s6-agent-hooks.rules.md`. Every row is advisory until the testing loop
confirms it against the written code. A row whose intent is quoted by a `checks/qg-s6-SC-*.sh`
script keeps that exact text as its case name.

**Test harness constraints:** bats runs in Docker with `/code` read-only and `HOME=/tmp/home`.
Hook cases that need a plugin checkout, a linked worktree or the tool-path file copy the plugin into
a writable `$WORK` folder. Hooks fire through real `git commit` and `git push`, and scripts run by
path, never as `bash <file>`, so their shebang applies. Each "same verdict" case needs a fixture the
injected name would pass if it leaked, plus a control showing the injection works in a plain shell.

### BP-1 Sandbox partitions

| variable | partition | expected | rows |
|---|---|---|---|
| Landlock ABI (`--max-abi`) | 5 / 6 | no marker, tool never runs / arms with scoping | T-66 |
| architecture | native / foreign entry | arms / killed, no socket | T-26, T-67 |
| syscall number | `0x3fffffff` / `0x40000000` / `io_uring_setup` | not filtered / `ENOSYS` / `ENOSYS` | T-68 |
| socket family | `AF_UNIX` / `AF_UNIX` with high bits set / `AF_INET`, `AF_INET6` / `socketpair(AF_UNIX)` | `EACCES` / `EACCES` / allowed / allowed | T-25, T-69, T-70 |
| descriptor | 0-2 / 3, 9, 255 | open / closed | T-27 |
| declared path | relative existing / relative missing / absolute / `..` / symlink / symlinked parent / `.git` component / `node_modules` / `node_modules/.vite` / `.` / empty | writable / created then writable / refused / refused / refused / refused / refused / refused / writable / refused / skipped | T-21..T-23, T-71..T-74 |
| SDK file | existing stamp, lockfile / new stamp, `engine.stamp.tmp.<pid>`, other SDK file | rewritable / denied | T-17, T-18 |
| `QG_SANDBOX_SDK` | unset | no SDK grant, no `FLUTTER_*` in the child | T-75 |
| tool-path entry | absolute outside work trees / relative, empty, missing, file, inside a work tree / duplicate | on `PATH` after system folders / dropped, doctor fails naming it / once | T-90..T-92 |

**Property invariants:** P1, a write succeeds exactly when its target lies in `QG_PRIVATE`, a grant,
`/dev/null` or an existing SDK stamp (T-76). P2, the tool's sentinel exists only when the armed
marker exists (T-77). P3, the child's environment holds only the names the rules list, whatever the
parent exports, for `QG_SANDBOX` 0 or 1 (T-78). P4, no private folder remains after a pass, a
failure or an unarmed run (T-79).

### AB-1 Agent bypass attempts

Each row names the guard whose removal makes its test fail.

| abuse | guard | rows |
|---|---|---|
| assign, export or `env` a denied name; `export BASH_ENV` alone; `bash -c 'BASH_ENV=…'` | denied-name list in assignments and declarations | T-100 |
| git replace, alternate, object-dir and external-diff names beside a git read | denied list checked before the read exemption | T-101 |
| `env 'X%=1' true`; `env FOO=1 'X%=1' BAR=2 git commit -n` | non-identifier denial and `=`-word consumption, each alone | T-102 |
| `export -f`, `declare -fx`, `declare -f -x`, `typeset -xf`, `builtin export -f`, `command declare -x -f` | denied-command rule across flag clusters and wrappers | T-103 |
| look-alikes `MY_BASH_ENV=1`, `echo BASH_ENV=x`, `declare -f`, `declare +x -f` | exact-name match | T-104 |
| writes and edits under the pub cache, a two-marker SDK, a copydetect venv folder | global write denials in both hooks | T-105 |
| startup-file writes, `cd` with no argument then `.bashrc` | startup list; `cd` to `HOME` | T-106, T-112 |
| writes under an early `PATH` folder or a tool-path folder, through a symlink | realpath compare and the tool-path reader | T-107 |
| denied root in Python or Node code, heredoc, and every write form of the rules | text match and target extraction | T-108 |
| planted `json.py`, `subprocess.py` in the cwd | `python3 -I` with the hook's own folder first | T-109 |
| edit in a linked worktree versus the hook checkout, its `.git`, a symlink into it | exemption keyed on the hook's own checkout | T-110 |
| `2>&1`, `>&2`, `2>&-` with the cwd in the plugin; twins `>&<path>`, `&>/code/x` | fd duplication allowance is digits or `-` only | T-111 |
| inline code or a cleared agent marker beside git, `.git`, a hook or the plugin | narrowing keyed on the whole input | T-113 |
| installed program naming the plugin; twins via symlink, `..`, redirect, chained command | realpath under the plugin cache, words only | T-114 |
