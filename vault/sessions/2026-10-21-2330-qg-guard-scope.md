# qg-guard-scope

## Goal
Stop the user-level agent guards refusing ordinary commands in repos with no gate, while keeping every rule that protects the guards themselves.

## Did
- Measured the refusals: 1,792 bash-guard refusals from 2026-10-14 to 2026-10-21, 0 on 10-17 and 575 on 10-21, across every project's transcripts.
- Added `templates/claude-hooks/gated.py`: a repo is gated when its common dir's `hooks/pre-commit` or `pre-push` holds `# vault-guard-start`. Anything unreadable, a set `hookspath`, and bare repos count as gated.
- Split `guard_bash.py` rules into `gate()` (recorded; denied in `main()` only when a scope path is gated) and `Integrity` (always). Opaque text sites call `opaque()`, which makes `main()` read the raw command for integrity paths.
- Split `guard-edit.sh` reasons the same way; `guard-stop.sh` ends a turn only on `gated.py` exit 3.
- Moved `mark_gated` into `tests/unit/guard-helpers.bash`; fixtures in four bats files now build gated repos. Full suite: 1037 ok.
- Committed `bb56155` on `fix/guard-open-commands` in `~/workspace/vault-quality-gates-opencmd`, on top of the run-time value relaxation `9657498`/`8df55ea` another session had already committed.

## Learned
- The live guard refuses edits to itself through Bash, and Claude Code auto mode refuses them through any tool. The operator had to leave auto mode before the guard could be changed.
- A gate rule that raised mid-scan would have hidden a later integrity write in the same command. Recording and deciding after the scan is what keeps the two classes independent.
- Scope must read raw text too: a gated path inside `bash -c '…'`, a pipe into `bash`, or `env -S` is one lexer word.
- `~/.claude/hooks/doc-lint-hook.sh` and the vault plugin's own doc-lint hook both run on every edit, so every lint finding prints twice.

## Behaviors & rules
- cwd in a repo with no `# vault-guard-start` hook, command reaches no gated path → `systemctl --user restart`, `bin/test-safe.sh`, `python3 -c "$v"`, `git commit -n` are allowed.
- any cwd, write to the plugin main worktree, installed plugin code or `*/.claude*/settings*.json` → denied with "ask the human to make this change".
- any cwd, write to global git config, `~/.config/husky/`, a shell startup file or a tool-path folder → denied the same way.
- ungated cwd, literal path into a gated repo (`git -C`, `cd`, `--git-dir=`, `bash -c` text, piped text) → every gate rule applies.
- `rm`/`mv`/`find -delete` on a folder holding `~/.claude`, the plugin or the plugin cache → denied everywhere.
- a computed `cd` or `git -C` followed by a writing git command → denied everywhere; edge: a read such as `git worktree list` passes.
- `gated.py` crash or any exit other than 3 → `guard-stop.sh` treats the repo as gated.
